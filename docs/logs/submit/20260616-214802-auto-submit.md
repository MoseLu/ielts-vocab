## Commit Body

Full audit of all 12,396 words in vocabulary_data/*.json and *.csv
against three public IPA sources:
  1. Wiktionary Action API (en.wiktionary.org) - primary RP/GA, batched
     50 titles per call, parses {{IPA|en|/.../|a=RP|...}} templates.
  2. Cambridge Dictionary (dictionary.cambridge.org) - UK and US
     sections, scraped via <span class="ipa dipa ...">.
  3. ipa-dict en_US (open-dict-data/ipa-dict) - local TSV, 125k
     entries, used as offline tiebreaker (no network cost).

The 2-source consensus rule normalizes IPA by stripping syllable
dots, length marks, stress marks, and (r)/(ə) placeholders, then
compares Wiktionary RP ↔ Cambridge UK (UK agreement) and
Wiktionary GA ↔ Cambridge US (US agreement).

Output:
  - all-words-audit.csv: per-word row with each source's IPA, the
    normalized form, and agreement flags.
  - checkpoint.json: incremental state, supports --resume after
    crashes or kill.
  - --start-from N: skip first N words (skip past a stuck range).
  - --batch-size, --cambridge-delay, --wikt-delay: tuneable
    throttling (defaults: 50 / 0.2s / 0.3s).

Limitations:
  - 0.2s/call × 12,396 = ~2.5h on the happy path; 8s timeout with
    one retry on Cambridge means worst case ~5h if Cambridge
    starts throttling.
  - The user reported in the spot-check that some Azure
    word-tts MP3s sounded wrong (e.g. 'power' rendered with no
    final /ə/). This script does NOT touch Azure or overrides;
    it only emits an audit report so the user can decide which
    IPA values to commit to overrides/TTS in a follow-up step.

Output is read-only by design (per user request: '只输出审计报告').
