## 核心设计判断

这组 UI 的关键不是简单的“图标 + 文本”拼贴，而是让文本进入美术容器：卡牌、礼盒、宝盘、飘带、铭牌、价格条和半透明任务行本身就是信息结构。复杂原画负责情绪和主题，文字只落在可读的承载物上。

### 商城

- 商城首页用大角色半身像建立消费主题，右侧推荐卡承接具体入口；主视觉和信息区分工明确。
- 商品页用蓝色卡片网格承载品类，卡片底部放标题或价格，减少文字对原画的破坏。
- 兑换页把货币图标紧贴数字，价格条作为统一底座，用户先识别资源图标，再读价格。
- 夺宝页把抽奖机制实体化成宝盘，购买按钮嵌在金色台座里，按钮本身也像场景物件。

### 活动

- 左侧使用时间线式导航，当前活动用蓝色光效标记，红点只承担“有新内容”的提示职责。
- 中间大海报负责活动情绪；右侧任务列表负责可执行信息，避免长文案压住主题角色。
- 任务行通常由奖励图标、进度数字、任务说明、行动按钮组成，信息密度高但扫描路径稳定。
- 关键数字用高亮色插入句子，按钮保持统一蓝色发光边框，使任务状态和行动点分离。

### 礼册

- 礼册首页用礼盒/画框隐喻承载当前奖励，奖励图不是孤立图片，而是被装进中心容器。
- 右侧任务像贴在礼盒旁的清单，奖励图标、数量和按钮在同一行内完成闭环。
- 惊喜折扣页把皮肤做成漂浮卡牌，折扣贴在卡角，价格贴在卡底，文本成为卡牌的一部分。
- 奖池弹窗使用半透明蓝色大面板，左侧分类、右侧奖品卡，保留游戏感同时控制阅读秩序。

## 可复用规则

- 文本必须有承载物：铭牌、飘带、底条、半透明面板、任务行、卡牌底座；避免裸贴在复杂插画上。
- 图标和数字绑定显示：货币图标贴近价格，奖励图标贴近任务，状态图标贴近标题。
- 容器先表达功能：宝盘代表抽奖，礼盒代表福利，卡牌代表商品，时间线代表活动进度。
- 主视觉和信息区分层：主视觉负责情绪，信息区负责阅读、选择、执行。
- 高亮只服务当前状态、关键数字、可点击按钮；普通说明文字保持低亮度，避免页面到处抢焦点。
- CTA 使用稳定的视觉语法：蓝色用于前往/完成类行动，金色用于购买/抽取/高价值行动。
- 长文本拆短：用短标题、进度数字、奖励图标和按钮替代整段说明。
- 装饰线条要参与分组：发光边、分割线、角标、底座应明确说明元素归属，不只做背景噪声。
- 卡片内文字优先放在底部或侧边，避开人物脸、武器、核心动作区域。
- 弹窗仍要像游戏世界的一部分：半透明大面板可以承载信息，但边框、标题牌、关闭按钮要保持主题化。

## 对本项目的落地提醒

- 学习首页、活动/任务、会员或奖励类页面可以借鉴“主题插画 + 右侧任务清单”的布局，而不是把所有内容做成普通表单卡。
- 单词、练习、奖励、错题、连续学习天数等状态，可以用小图标和数字绑定，不要只靠文字说明。
- 复习计划、打卡、领取奖励等场景，优先设计带功能隐喻的容器，例如计划卷轴、奖励盒、进度轨道、错题卡。
- 保持本项目的学习产品气质，不照搬高饱和商业游戏皮肤；可借鉴的是图文融合规则、层级组织和容器语言。
